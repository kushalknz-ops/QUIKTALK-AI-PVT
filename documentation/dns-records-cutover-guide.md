# Quiktalk AI — DNS Records & Cutover Guide
# QTK-012, QTK-021, Stage 2

This guide contains the exact, copy-paste DNS records and execution sequence required for the production cutover to Cloudflare Pages and Hostinger email security.

---

## 1. Prerequisites Checklist

- [ ] **Create DMARC Reporting Mailbox**: Log into Hostinger hPanel -> **Emails** -> create `dmarc-reports@quiktalkai.com`. (MUST be created before publishing the DMARC record to prevent bounce loops).
- [ ] **Generate DKIM in Hostinger**: Go to Hostinger hPanel -> **Emails** -> select `quiktalkai.com` -> **DKIM** -> Click **Generate** (uses default selector, typically `default` or `hostingermail1`).
- [ ] **Audit Live SPF Record**: Confirm that current email routing uses Hostinger mail servers.

## 2. DNS Records to Configure

### A. Email Security Records (Hostinger Verified Baseline)

| Type | Name / Host | Value / Target | TTL | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **TXT** | `@` | `v=spf1 include:_spf.mail.hostinger.com ~all` | 3600 | **KEEP Hostinger SPF baseline** (verified live in audit). *Do NOT change to Google Workspace unless mailboxes are migrated.* |
| **TXT** | `<selector>._domainkey` | `v=DKIM1; k=rsa; p=<PUBLIC_KEY_FROM_HPANEL>` | 3600 | Generated from Hostinger hPanel. Selector name & date recorded below. |
| **TXT** | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@quiktalkai.com; pct=100; sp=quarantine` | 3600 | Directs unaligned/spoofed mail to spam/quarantine; sends daily aggregate reports to the dedicated mailbox. |

#### DKIM Publication Log
- **Selector Name**: `default` (or as generated by Hostinger hPanel)
- **Generation Date**: `YYYY-MM-DD`
- **Verification Tool**: `dig TXT <selector>._domainkey.quiktalkai.com +short`

### B. Cloudflare Pages Web Hosting & Apex Redirect

When deploying on Cloudflare Pages:

| Type | Name / Host | Value / Target | Proxy Status | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **CNAME** | `www` | `<project-name>.pages.dev` | Proxied (Orange Cloud) | Primary canonical hostname for Quiktalk AI. |
| **CNAME** | `staging` | `<project-name>.pages.dev` | Proxied (Orange Cloud) | Staging host — access-protected via Cloudflare Access or Basic Auth. |

#### Single-Hop Apex-to-WWW Redirect Rule
In Cloudflare Dashboard -> **Rules** -> **Redirect Rules** (or Page Rules):
- **Rule Name**: `Apex to Canonical WWW 301`
- **Incoming match**: `(http.host eq "quiktalkai.com")`
- **Action**: Dynamic Redirect
- **Target URL**: `concat("https://www.quiktalkai.com", http.request.uri.path)`
- **Status Code**: `301 Moved Permanently`
- **Preserve query string**: Yes

> This ensures `http://quiktalkai.com`, `http://www.quiktalkai.com`, and `https://quiktalkai.com` collapse into **exactly one 301 hop** to `https://www.quiktalkai.com/`.

## 3. Post-Publication Verification Sequence

1. **Verify SPF**:
   ```bash
   dig TXT quiktalkai.com +short
   # Expected: "v=spf1 include:_spf.mail.hostinger.com ~all"
   ```

2. **Verify DKIM**:
   ```bash
   dig TXT <selector>._domainkey.quiktalkai.com +short
   # Expected: "v=DKIM1; k=rsa; p=..."
   ```

3. **Verify DMARC**:
   ```bash
   dig TXT _dmarc.quiktalkai.com +short
   # Expected: "v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@quiktalkai.com; pct=100; sp=quarantine"
   ```

4. **Verify Single-Hop Redirect Collapse**:
   ```bash
   curl -IL http://quiktalkai.com
   # Hop 1: HTTP 301 -> https://www.quiktalkai.com/
   # Hop 2: HTTP 200 https://www.quiktalkai.com/ (Strictly 1 redirect)
   ```

5. **Send Test Email**:
   - Send test email from your Quiktalk AI business mailbox to [https://www.mail-tester.com](https://www.mail-tester.com) and confirm a **10/10 deliverability score**.
